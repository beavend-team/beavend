# ADR-014: Model Context Protocol (MCP) and Parameterized SQL Template Tool Executors

## Status
Accepted

## Context
Beavend acts as an application-facing AI runtime that connects client apps to models and model calls to external systems on behalf of authenticated end users. In Phase 8 (Tool Engine & Downstream Auth), we established the foundational tool orchestration loop, SSRF defenses via `SafeDialer`, and confused-deputy protection via server-injected identity bindings. However, executor support was limited to HTTP and Webhook endpoints.

According to PRD §17.2, §17.4, and the roadmap:
1. **Model Context Protocol (MCP)**: Standardized open protocol for AI models to discover and execute tools hosted by MCP servers. Implementors increasingly expose tools through MCP servers over HTTP/SSE or JSON-RPC 2.0.
2. **SQL Templates**: Implementors often need AI agents to query existing databases (e.g. PostgreSQL, SQLite, MySQL) for user-specific data (orders, profile info, transaction history) without building dedicated HTTP endpoints. However, allowing LLMs to generate arbitrary SQL is an enormous security risk (SQL injection, accidental deletion, unauthorized cross-tenant data access).

## Decision
1. **Model Context Protocol (MCP) Executor**:
   - Implement `tools.MCPExecutor` conforming to `core.Executor`.
   - Dispatch JSON-RPC 2.0 `tools/call` requests over HTTP/SSE:
     ```json
     {
       "jsonrpc": "2.0",
       "id": "<request_id>",
       "method": "tools/call",
       "params": {
         "name": "<tool_name>",
         "arguments": { ... }
       }
     }
     ```
   - Support both standard JSON-RPC 2.0 responses and SSE stream payloads (`data: {...}`).
   - Enforce SSRF protection using `SafeDialer` (prohibiting loopback, private RFC1918 ranges, link-local, and cloud metadata).
   - Support all downstream auth modes (`forward_user_token`, `token_exchange`, `service_token`, `signed_headers`, custom headers).
   - Sanitize all MCP tool output (size bounds, PII redaction, transformation).

2. **Parameterized Read-Only SQL Template Executor**:
   - Implement `tools.SQLTemplateExecutor` conforming to `core.Executor`.
   - **Zero LLM-Generated SQL**: The SQL query is a pre-defined template created by the administrator in configuration, never generated by the model.
   - **Read-Only Enforcement**: Query templates are validated at configuration and execution time. Mutating statements (`INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `TRUNCATE`, `GRANT`, `REVOKE`, `CREATE`, etc.) and multi-statement queries (separated by `;`) are strictly rejected.
   - **Dialect Parameter Binding**:
     - Templates use named placeholders (`:param`, e.g. `:user_id`, `:limit`).
     - Dialect transformation converts `:param` to positional parameters (`$1, $2` for PostgreSQL; `?` for SQLite/MySQL).
     - Values are bound as typed parameters using standard `database/sql` driver queries, never string interpolation.
   - **Confused-Deputy Defense**: Identity parameters such as `:user_id` and `:subject` are automatically populated from the verified token `Identity.Subject` when not explicitly overridden by bindings.
   - **Connection Pooling**: Managed via `SQLConnectionPool` with max open connections, idle connection reuse, and connection lifetime management.

3. **Executor Registry & Agent Loop**:
   - Integrate `MCPExecutor` and `SQLTemplateExecutor` into `DefaultExecutorRegistry`.
   - Support caching for idempotent MCP and SQL tool executions scoped by `(project, env, subject, tool_id, args_hash)`.

4. **Control Plane & Dashboard**:
   - Add tool configuration validation for MCP URLs and SQL templates.
   - Add `POST /v1/admin/tools/{id}/test` endpoint for interactive testing with mock caller identities.
   - Provide visual executor type selectors and SQL template editor in the Admin Dashboard.

## Consequences
- **Positive**:
  - Implementors can seamlessly integrate standard MCP server tools into Beavend AI Apps.
  - Implementors can securely expose read-only database views to AI agents without creating custom web APIs.
  - Absolute protection against SQL injection and data mutation.
  - Confused-deputy defense guarantees that users can only query their own data when templates use `:user_id` or identity bindings.
  - Full observability and tracing on tool executions.
- **Negative / Trade-offs**:
  - Direct database connections require the Beavend server to have network egress to the implementor's database. Implementors must provision read-only database credentials with least privilege.

## Alternatives Considered
- **LLM-Generated SQL with Read-Only DB User**: Rejected as too dangerous; read-only roles can still cause denial-of-service via expensive queries, read unintended tables, or exploit DB functions. Pre-defined parameterized templates provide strict compile-time safety.
- **Client-Side Only MCP**: Rejected because client-side MCP cannot access server-side databases or private microservices securely.
